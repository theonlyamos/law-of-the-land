# Document publishing

**Owners:** Content Manager uploads; a different Content Reviewer approves and publishes. A Super Administrator may upload, approve, and publish the same version in every environment. **Abort:** the jurisdiction's Gemini search is not ready, the jurisdiction is disabled, source/checksum validation fails, a non-super-admin reviewer equals the uploader, checklist/evaluation is incomplete, step-up fails, or another lifecycle job is non-terminal.

1. In `/admin/documents/<resourceId>`, upload the governed original and invoke `admin/documents:createDocumentVersion` with `{ resourceId, storageId, filename, mimeType, byteSize, sha256, sourceUrl, effectiveAt }`. Expected state is `ready_for_review`; validated upload records the immutable original and makes it available to the review docket immediately. Upload, review, and approval make no provider request and create no provider job.
2. In `/admin/review`, a different reviewer invokes `admin/reviews:approveVersion({ versionId, checklistAnswers, evaluationRunId, reason, idempotencyKey })`; every checklist value must be `true`. A `super_admin` may approve their own upload; this role exception is identical in development and production. Expected state is `approved`.
3. In `/admin/review`, choose publish. Password step-up is bound to action `document_publish`, target `versionId`, and the same new idempotency key. Invoke `admin/publication:publishVersion({ versionId, confirmation: "PUBLISH <versionId>", reason, idempotencyKey })`. Only this publish step sends the immutable original for Gemini indexing. Expected state is `publishing`, then `published`; when replacing a version, the previous indexed document is removed before the active pointer changes atomically.
4. After publish is accepted, observe the `Index document` job in `/admin/operations`. It displays `Waiting for Gemini` and `Next check in {duration}`. Poll delays are 5, 10, 20, 30, then 60 seconds, capped at 60 seconds until 2 hours have elapsed; pending operations are then checked every 5 minutes. The review window is 6 hours from initial provider acceptance or the latest explicit safe Retry. A poll that still reports pending at or after that deadline moves the job to `manual_review`, displayed as `Indexing needs review`; legal research for the jurisdiction remains paused and its lifecycle lock remains held. Provider errors or lease-recovery failures may require review earlier. The longer window does not guarantee Gemini success.

Deploying this policy does not resume a job already in `manual_review`. An administrator must review the evidence and use the existing safe Retry control to resume the same persisted provider operation with a fresh 6-hour window, without uploading the document again. Follow [provider outage and stuck-job recovery](provider-outage.md).

Only publish may send a version to Gemini; review and merely approved versions never do. Unpublish removes the active indexed document; rollback indexes the selected approved version and removes the former active document through the same durable lifecycle.

Legal research performs one File Search call across the complete server-authorized set of one to four ready jurisdiction stores. Convex remains authoritative for access, titles, URLs, versions, and citations. Never copy Gemini store, document, or operation names into browser-visible notes or incident evidence.

Abort on any unexpected correlation ID, state, or provider outcome. A failed replacement returns the candidate to `approved`, records `Publishing failed. The previous published version is still active.`, releases the safe lock, and preserves the old pointer. A failed first publish records `Publishing failed. No version was published.` Recovery is to open an incident, correct the fault, and start a new approved publication attempt with a new idempotency key; never submit a duplicate provider request for an uncertain outcome. Follow [provider outage and stuck-job recovery](provider-outage.md).
