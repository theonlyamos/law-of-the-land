# GroundX provider outage and stuck jobs

**Owner:** on-call Super Admin. **Abort dependent work:** authentication/validation failure, retry budget exhausted, or any uncertain copy/delete outcome. Do not retry, cancel, publish, unpublish, or rollback when the provider outcome is unknown.

1. Open `/admin/incidents` and invoke `admin/operations:createIncident` with `{ title, severity, reason, idempotencyKey }`; use a fresh UUID key and `critical` when search or active publication is affected. Expected state: `open`, one correlation ID, and one `incident.created` audit. Assign the owner with `admin/operations:updateIncident({ incidentId, ownerId, reason, idempotencyKey })`, again using a new key. Abort if either correlation ID is absent.
2. Open `/admin/operations` and filter `admin/jobs:listJobs` by status/type. Automatic retries for `network`, `timeout`, and `rate_limit` occur after 1, 5, and 20 minutes; the next failure becomes `manual_review`. Authentication, validation, and provider failures become `failed`.
3. Never cancel `running`, `waiting_callback`, `manual_review`, or document-version jobs. `admin/jobs:cancelJob({ jobId, reason, idempotencyKey })` is valid only for an unleased queued non-document job with no process ID; expected state is `cancelled`.
4. After correcting the provider condition, retry only a `manual_review` job that has a process ID and retryable last error. Invoke `admin/jobs:retryJob({ jobId, reason, idempotencyKey })` with a new UUID. Expected state is `running`; a retryable failed non-document job without a process may instead become `queued`. Abort on `Integration job is not retryable` and do not change the row manually.
5. Remote ingest completes primarily by authenticated callback. Copy/delete are provider-limited polling exceptions; the 15-minute reconciler observes their existing process rather than creating a second provider operation.
6. Add sanitized progress with `admin/operations:addIncidentNote({ incidentId, note, reason, idempotencyKey })`. Do not include tokens, URLs containing tokens, raw provider bodies, chat text, or document content.

Recovery is complete only when every affected job is terminal, the active production pointer remains healthy, and an authorized GroundX smoke has actually passed. Until then label GroundX **configured**, not healthy. Move the incident to `monitoring`, then `resolved`, with separate `admin/operations:updateIncident` calls and new idempotency keys. If recovery fails, leave publication locked, preserve the prior pointer, and escalate without replaying the provider request.
