# Gemini provider outage and stuck jobs

**Owner:** on-call Super Admin. **Abort dependent work:** authentication or validation failure, retry budget exhausted, or any uncertain indexing/deletion outcome. Do not retry, cancel, publish, unpublish, or roll back while the provider outcome is unknown.

1. Open `/admin/incidents` and invoke `admin/operations:createIncident` with `{ title, severity, reason, idempotencyKey }`; use a fresh UUID key and `critical` when legal research or active publication is affected. Expected state: `open`, one correlation ID, and one `incident.created` audit. Assign the owner with `admin/operations:updateIncident({ incidentId, ownerId, reason, idempotencyKey })`, again using a new key. Abort if either correlation ID is absent.
2. Open `/admin/operations` and filter by Gemini job type and state. Jobs are labeled `Set up jurisdiction search`, `Index document`, `Remove indexed document`, and `Remove jurisdiction search store`. An accepted index operation displays `Waiting for Gemini`; its next poll is scheduled after 5, 10, 20, 30, then at most 60 seconds.
3. Never cancel `running`, `waiting_provider`, `manual_review`, or document-version jobs. `admin/jobs:cancelJob({ jobId, reason, idempotencyKey })` is valid only for an unleased queued non-document job with no known provider operation; expected state is `cancelled`.
4. At 30 minutes without confirmed indexing completion, Operations displays `Indexing needs review`. The affected jurisdiction is unavailable for legal research and its lifecycle lock remains held. Use `View provider job`, inspect sanitized evidence, and preserve the existing provider operation; do not create a replacement upload.
5. After correcting a known provider condition, use only the existing safe retry/manual-review control exposed for that job. Supply a new UUID and reviewed reason. An exact persisted operation is polled again; an uncertain deletion is reconciled without issuing a second delete. Abort on `Integration job is not retryable` and never edit the row manually.
6. Add sanitized progress with `admin/operations:addIncidentNote({ incidentId, note, reason, idempotencyKey })`. Do not include API keys, signed URLs, Gemini resource names, raw provider bodies, chat text, or document content.

Move the incident to `monitoring`, then `resolved`, with separate `admin/operations:updateIncident` calls and fresh idempotency keys only after every affected job is terminal, legal research is restored, and pointer/index state agrees. If recovery fails, leave publication locked, preserve the prior pointer, and escalate without replaying the provider request. Operations may report the integration as **Configured** from server-side key presence; this is not a provider-health claim. Provider health and release completion remain unverified until Task 7's separately authorized real smoke succeeds.
