# Gemini provider outage and stuck jobs

**Owner:** on-call Super Admin. **Abort dependent work:** authentication or validation failure, retry budget exhausted, or any uncertain indexing/deletion outcome. Do not retry, cancel, publish, unpublish, or roll back while the provider outcome is unknown.

1. Open `/admin/incidents` and invoke `admin/operations:createIncident` with `{ title, severity, reason, idempotencyKey }`; use a fresh UUID key and `critical` when legal research or active publication is affected. Expected state: `open`, one correlation ID, and one `incident.created` audit. Assign the owner with `admin/operations:updateIncident({ incidentId, ownerId, reason, idempotencyKey })`, again using a new key. Abort if either correlation ID is absent.
2. Open `/admin/operations` and filter by Gemini job type and state. Jobs are labeled `Set up jurisdiction search`, `Index document`, `Remove indexed document`, and `Remove jurisdiction search store`. An accepted index operation displays `Waiting for Gemini`; poll delays are 5, 10, 20, 30, then 60 seconds, capped at 60 seconds until 2 hours have elapsed, followed by 5-minute checks. Elapsed time is measured from initial provider acceptance or the latest explicit safe Retry.
3. Never cancel `running`, `waiting_provider`, `manual_review`, or document-version jobs. `admin/jobs:cancelJob({ jobId, reason, idempotencyKey })` is valid only for an unleased queued non-document job with no known provider operation; expected state is `cancelled`.
4. If a poll still reports indexing pending at or after the 6-hour review deadline, the job enters `manual_review` and Operations displays `Indexing needs review`. Provider errors or lease-recovery failures may require review earlier; the longer window does not guarantee Gemini success. The affected jurisdiction is unavailable for legal research and its lifecycle lock remains held. Use `View provider job`, inspect sanitized evidence, and preserve the existing provider operation; do not create a replacement upload.
5. After correcting a known provider condition, use only the existing safe Retry/manual-review control exposed for that job. Supply a new UUID and reviewed reason. An exact persisted indexing operation returns to `running` for an immediate poll, then `waiting_provider` while pending, with a fresh 6-hour review window. Retry preserves the cumulative poll count: a mature operation resumes 60-second pending checks for the first 2 hours of the new window, then 5-minute checks. It keeps the same provider operation and does not upload again. Deploying this policy does not resume an existing `manual_review` job: the administrator must explicitly use the safe Retry control. An uncertain deletion is reconciled without issuing a second delete. Abort on `Integration job is not retryable` and never edit the row manually.
6. Add sanitized progress with `admin/operations:addIncidentNote({ incidentId, note, reason, idempotencyKey })`. Do not include API keys, signed URLs, Gemini resource names, raw provider bodies, chat text, or document content.

Move the incident to `monitoring`, then `resolved`, with separate `admin/operations:updateIncident` calls and fresh idempotency keys only after every affected job is terminal, legal research is restored, and pointer/index state agrees. If recovery fails, leave publication locked, preserve the prior pointer, and escalate without replaying the provider request. Operations may report the integration as **Configured** from server-side key presence; this is not a provider-health claim. Provider health and release completion remain unverified until Task 7's separately authorized real smoke succeeds.
